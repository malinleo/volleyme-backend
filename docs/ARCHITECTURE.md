# Архитектура volleyme-backend

Бэкенд на **Python 3.14**, **FastAPI**, **SQLAlchemy 2 (async)** и **PostgreSQL** (драйвер `asyncpg`). Сборка и зависимости — **Poetry**. Слой приложения построен в духе **чистой/гексагональной архитектуры**: домен не зависит от фреймворков, сценарии (use cases) оркестрируют домен и порты, инфраструктура подставляется через **dependency-injector**.

---

## Высокоуровневая схема слоёв

```
┌─────────────────────────────────────────────────────────────┐
│  presentation (FastAPI: роутеры, схемы, deps, обработчики)   │
└───────────────────────────┬─────────────────────────────────┘
                            │ вызывает use cases, маппит DTO ↔ HTTP
┌───────────────────────────▼─────────────────────────────────┐
│  application (use cases, DTO, query-repos как Protocol,       │
│               сервисы-порты: токен, auth, валидаторы)        │
└───────────────┬─────────────────────────────┬─────────────────┘
                │                             │
                │ использует                │ абстракции (Protocol)
┌───────────────▼─────────────────────────────▼─────────────────┐
│  domain (агрегаты, типы, доменные исключения, репозитории     │
│          как Protocol — только контракты)                      │
└───────────────────────────────────────────────────────────────┘
                            ▲
                            │ реализуют
┌───────────────────────────┴───────────────────────────────────┐
│  infra (SQLAlchemy: модели, репозитории, сессии; JWT, пароли;  │
│         DI-контейнеры)                                         │
└───────────────────────────────────────────────────────────────┘

         ┌──────────────────┐
         │  common + config │  — общие базовые вещи и настройки
         └──────────────────┘
```

Направление зависимостей: **presentation → application → domain**; **infra** зависит от **domain** и **application** (реализации портов), но не наоборот.

## Пакеты и роли

### `src/config`

Настройки приложения (**pydantic-settings**): URL БД, JWT, лимиты пагинации и т.д. Используются в `infra` и `presentation`.

### `src/common`

Переиспользуемый «скелет» для use cases и работы с БД:

- **`usecases`** — базовый `BaseUseCase`, общие исключения сценариев (`NotFound`, `Unauthorized`, …), валидаторы.
- **`models`** — базовые SQLAlchemy-модели и фабрика/получение сессии (`get_db_session`), на которые опирается инфраструктура репозиториев.
- **`exc`**, **`dto`**, **`entities`**, **`schemas`**, **`registry`** — общие примитивы для ошибок и структур данных.

Это не домен Volleyme, а общая инфраструктурная/прикладная обвязка.

### `src/volleyme/domain`

**Ядро предметной области:**

- **`aggregates`** — сущности с инвариантами (`Event`, `User`, `Player`, `EventInvitation`, …).
- **`repos`** — **Protocol**-репозитории команд (загрузка/сохранение агрегатов), без SQL.
- **`types`** — идентификаторы и прочие типизированные значения (`EventId`, `UserId`, …).
- **`enums`**, **`exc`** — доменные перечисления и ошибки.

Здесь нет FastAPI и SQLAlchemy.

### `src/volleyme/application`

**Слой сценариев:**

- **`usecases`** — классы с `execute(...)`, наследуют `common.usecases.BaseUseCase`; координируют репозитории, сервисы и валидацию; бросают `usecases.exc.*`.
- **`dto`** — объекты передачи данных **между** use case и внешним миром (списки событий, детали и т.д.).
- **`query_repos`** — **Protocol** для **чтения** в форме уже подготовленных DTO (CQRS-лёгкий вариант: отдельно от командных репозиториев домена).
- **`services`** — порты и реализации на уровне приложения: стратегии аутентификации, **Protocol** `TokenService`, валидаторы бизнес-правил (`can_join_event`, …).

Use cases зависят от **доменных** портов и от **application**-портов; конкретные реализации подставляются из `infra`.

### `src/volleyme/infra`

**Технические детали:**

- **`db/models`** — SQLAlchemy-модели таблиц.
- **`db/repos`** — реализации доменных `repos.*` и (где нужно) логика на базе `SQLAlchemyModelRepo` из `repos/base/sqlalchemy.py`.
- **`db/migrations`** — Alembic.
- **`services`** — JWT (`JWTCodecService` и стратегии), пароли, email/password auth и т.д.
- **`di`** — **dependency-injector**:
  - **`Infra`** — движок БД, `async_sessionmaker`, `db_session`, фабрики репозиториев и сервисов.
  - **`Usecases`** — фабрики use cases с внедрёнными зависимостями из `Infra`.
  - **`DI`** — корневой контейнер, **wiring** на модули `presentation.rest.endpoints` и `deps`.

### `src/volleyme/presentation`

**HTTP-слой:**

- **`rest/main.py`** — создание `FastAPI`, подключение роутеров, `container.wire(...)`, глобальные `exception_handler` для ошибок use cases.
- **`rest/endpoints`** — роутеры; через `@wiring.inject` и `Provide[DI.usecases.*]` получают конкретный use case на запрос.
- **`rest/schemas`** — Pydantic-схемы запросов/ответов (маппинг к/из DTO).
- **`rest/deps.py`** — зависимости FastAPI (аутентификация через контейнер и `AuthUseCase`, пагинация).
- **`rest/exc_handlers`** — перевод доменных/прикладных ошибок в HTTP-ответы.

### Прочее

- **`tasks.py`**, **`inv/`** — вспомогательные скрипты/утилиты (не ядро API).

## Связи между слоями (кратко)

| Откуда        | Куда              | Что передаётся |
|---------------|-------------------|----------------|
| Presentation  | Application       | Вызов `usecase.execute`, DTO на выходе |
| Presentation  | Infra (DI)        | Только разрешение зависимостей через контейнер |
| Application   | Domain            | Агрегаты, типы, вызовы `Protocol` репозиториев |
| Application   | Application       | DTO, query-repos Protocol, TokenService и др. |
| Infra         | Domain            | Реализация `domain.repos.*` |
| Infra         | Application       | Реализация `query_repos`, сервисов (JWT, пароль, …) |

**Разделение команд и запросов:** изменение состояния идёт через доменные репозитории и агрегаты; «толстые» выборки для API — через `application.query_repos` с возвратом DTO.

## Запуск и окружение

- **docker-compose.yml** — типично БД и сервисы для локальной разработки.
- Точка входа API — приложение FastAPI из `presentation/rest/main.py` (uvicorn в документации/скриптах проекта).

## Резюме

Проект следует **слоистой архитектуре с инверсией зависимостей**: домен и сценарии описывают **что** делать и **контракты** доступа к данным и внешним сервисам; **infra** содержит **как** это сделать (БД, JWT, DI); **presentation** превращает HTTP в вызовы сценариев и обратно. Общий каркас use cases и сессий вынесен в **`src/common`**, специфика Volleyme — в **`src/volleyme/*`**.
